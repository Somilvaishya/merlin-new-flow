New · WIP (Work in Progress) Creation & Tracking
WIP Stage — Before Manufacturing Order Execution
Before the Work Order moves to full execution, raw materials are issued to production floor and moved into a dedicated WIP Warehouse. This creates a clear separation between raw stock, in-production stock, and finished goods — enabling accurate real-time inventory visibility at every stage.
  • Stock Entry (Material Issue) → moves RM from Main WH to WIP Warehouse
  • WIP Warehouse acts as the production floor holding zone
  • Each Job Card references WIP batch — operator can see exactly what's on floor
  • WIP qty visible in live stock dashboard — separate from sellable stock
  • On Work Order complete → WIP consumed → FG posted to BIN WH for QC
⚙ Stock Entry (Material Issue to WIP WH) 🏭 WIP Warehouse (new WH node) 📊 Real-time WIP stock report 👤 Production Supervisor

New · Pre-order Reserve at Individual Item Level
Item-level Stock Reservation for Pre-orders
When a Pre-order SO is confirmed, each line item's quantity is reserved independently at the item level — not as a bundle. As stock becomes available (post-QC or post-manufacture), it is auto-allocated to the oldest waiting pre-order for that item.
  • Each item on SO gets a dedicated stock reservation entry in ERPNext
  • Reserved qty deducted from "Available to Promise" (ATP) for that item
  • New stock (from QC pass or manufacture) auto-fills oldest pending reservation first
  • Customer notified when their reserved item is ready for dispatch
  • Partial release: if only some items are available, partial DN created for ready items
⚙ ERPNext Reserved Qty field on SO 📊 Stock Reservation Report 🔁 Auto-allocation on QC pass 👤 Sales + Warehouse Team

New · End-to-End Traceability for Return Orders
Return Traceability Chain
Every return order is fully traceable back to its original Sales Order, Delivery Note, Batch No., and even the Manufacturing / Subcontracting source. This allows Merlin to identify whether a return is linked to a specific production batch, vendor, or courier — enabling root-cause analysis and vendor accountability.
  • Sales Return links back to original SO, DN, Sales Invoice — one click history
  • Batch No. on returned item traced back to Work Order / Subcontracting Receipt
  • If multiple returns from same batch → batch flagged for investigation
  • Return reason + QC result linked to original vendor / production operator record
  • Traceability report: Batch → Original PO/WO → QC pass → SO → DN → Return → QC → Final WH
  • Clickpost RTO tracking ID linked to Sales Return DocType
